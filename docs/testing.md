# Testing

The goal is that a bug in the merge algorithm cannot reach a user's document unnoticed. Every
layer below checks something the others can't.

```bash
swift test                                              # everything (~90 s, debug build)
swift test --filter Fuzz                                # fuzzing only
EGWALKER_FUZZ_ITERS=20000 swift test --filter Fuzz      # soak run
EGWALKER_FUZZ_SEED=1000123 swift test --filter differentialTwoReplicas   # reproduce one case
swift build --build-tests --sanitize=address && \
  ASAN_OPTIONS=detect_leaks=0 swift test --skip-build --sanitize=address --disable-xctest
Scripts/mutate.py --limit 110 --seed 7                  # mutation testing (~1.5 h)
```

The paper-trace tests need `Scripts/fetch-traces.sh` first. Without the traces, those tests
are skipped and everything else still runs.

## Layers

| Layer | What it proves | Where |
|---|---|---|
| Unit | Basic editing, concurrency, README example, agent-name regression, incremental merge over a real history | `EngineTests.swift` |
| Conformance | Thousands of histories generated by diamond-types, each with the expected text; the optimized walker runs with **full tree validation after every step** | `conformanceSuite` |
| Real histories | Git imports of nodejs and git; the paper's S1–A2 traces exported with original agent names: byte-identical to diamond-types, under both traversal orders | `rawTraces`, `dtExported` |
| Differential fuzzing | Random multi-replica sessions agree with the oracle, converge, keep invariants, and incremental merge equals checkout | `FuzzTests.swift` |
| Mutation-driven | Targeted scenarios that mutation testing showed were missing | `MutationGapTests.swift` |
| Sanitizer | No memory errors in the unsafe code | ASan run |
| Mutation testing | The suite notices plausible bugs | `Scripts/mutate.py` |

## The oracle

`ReferenceWalker` is a line-by-line port of Joseph Gentle's TypeScript reference
implementation. It is slow (O(n²)), short and easy to check against the original. It passes
the same conformance suite as diamond-types. Wherever the optimized engine disagrees with it,
the optimized engine is wrong.

## Differential fuzzing

`FuzzTests.runCase(seed:steps:replicas:validateTree:)` simulates 2–5 replicas:

- local edits: inserts of 1–4 characters, deletes of 1–3, sometimes several in a row to form
  runs;
- the alphabet is mostly ASCII, plus `ö`, `é`, a combining diaeresis, `€`, `😀`, `日` and
  newlines. This exercises all three gap-buffer widths and multi-scalar graphemes;
- agent names are shuffled so byte order differs from creation order, including a non-ASCII
  name (`Éva`);
- random syncs between replicas.

At every sync it checks:

1. optimized checkout == reference checkout;
2. the same with depth-first traversal forced for every region (`dfsMinEntries: 2`);
3. the long-lived `TextDocument`, updated only by `merge`, equals the reference;
4. B-tree invariants (in a subset of cases).

At the end, all replicas merge everything and must converge to the reference text.

Every case comes from a SplitMix64 seed, so failures reproduce exactly.

## Mutation testing

Mutation testing measures the tests, not the code. `Scripts/mutate.py` inserts one plausible
bug at a time into the core files: relational (`<` ↔ `<=`, `==` ↔ `!=`), arithmetic (`+` ↔ `-`),
off-by-one (`± 1` → `± 2`), logical (`&&` ↔ `||`), boolean, and removed negations. For each
mutant it rebuilds and runs a fast gate of about 12 seconds.

- **Killed:** some test failed. Good.
- **Survived:** all tests passed. Either the tests have a blind spot, or the mutant is
  *equivalent* (it can't change behaviour). A human must decide which.

Results for a random sample of 110 out of 869 candidates (seed 7):

| | Mutants |
|---|---|
| Killed on the first run | 93 (84.5%) |
| Real test gaps, now closed by new tests and asserts | 6 |
| Performance-only (behaviour unchanged, slower) | 4 |
| Metrics-only (statistics fields) | 2 |
| Equivalent | 5 |
| **Killed after triage** | **99 (90.0%), i.e. every behaviour-changing mutant in the sample** |

Full triage, with the reasoning for every survivor: [`Benchmarks/mutation/TRIAGE.md`](../Benchmarks/mutation/TRIAGE.md).

What the survivors taught us:

1. **Output-only tests can't see compactness.** Breaking run-length merging yields the same
   text, just slower and larger. Structural assertions (`entryCount`, `runCount`) and the
   compactness invariant now catch it.
2. **A test can be accidentally blind.** The first run-length test typed at LV 0, where `a - 0`
   and `a + 0` coincide.
3. **Raw pointers don't trap.** Reading span `-1` returned a neighbour's memory silently. The
   raw accessors now `assert` their bounds in debug builds.
4. **Gate ≠ suite.** One mutant survived only because the fast gate omitted a relevant test.
   `mutate.py --recheck` re-runs survivors against the full suite.
5. **Fuzzers need scenarios, not just randomness.** Random editing never produced a backspace
   run whose middle is the parent of a concurrent branch. A dedicated test builds exactly that.

Runner commands:

```bash
Scripts/mutate.py --limit N --seed S        # campaign (resumable)
Scripts/mutate.py --report                  # regenerate REPORT.md
Scripts/mutate.py --recheck                 # survivors vs. full suite
Scripts/mutate.py --verify File.swift:123   # re-apply one survivor against the current gate
```

The runner rebuilds once per mutant, which takes about 45 s. Tools like swift-mutation-testing
(macOS) compile all mutants once behind a runtime switch ("schemata") and are much faster.

## The A2 lesson

On the paper's anonymised `A2.json`, our output had the right length but different content
from `endContent`. That is not a bug. The format replaces agent names with numbers, and A2
contains concurrent inserts at the same position, which are ordered by agent name.
diamond-types itself warns about this when exporting.

`dt-export` (in `Benchmarks/rust-dt-bench`) exports `.dt` files with the original names and
the delete direction. With those, A2 is byte-identical. The anonymised-format test therefore
checks A2 by length only, and the exact check uses the `.dt` export.

## Regressions found by tests during development

- **Unicode-equal agent names.** A real git history contains one author in two Unicode
  normalisation forms. Swift's `String ==` merged them into one agent; Rust and JS keep two.
  Fixed by keying agents on UTF-8 bytes, with a regression test.
- **Overlapping moves.** `moveUpdate(from:count:)` must not be used on overlapping ranges, and
  shifting spans inside a leaf overlaps by nature. Debug builds caught it on the first run.
  Fixed with an overlap-safe `memmoveElements`.
